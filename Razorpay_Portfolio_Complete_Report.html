🎯 Problem Statement

Every online payment carries a hidden question: is this transaction genuine, or is it fraud? Payment platforms must answer that question in milliseconds, for millions of transactions a day, and get it right in both directions — missing fraud causes direct financial loss, while wrongly blocking a real customer costs revenue and trust. This project builds the decision layer (a trained anomaly-detection model) and the risk-operations tooling around it, so a human analyst can see, trust, and act on the model's scores.

🏦 FinTech Industry Context

💡 Fraud detection is one of the highest-value applied-ML problems in FinTech — it sits directly on the P&L, not just on a metrics dashboard.
  • Digital payment volume has grown faster than manual review teams can scale — automation is no longer optional.
  • Industry tools (Stripe Radar, PayPal Fraud Protection, Razorpay's own risk engine) all follow the same core pattern: score → route → explain → monitor.
  • Regulators and merchants increasingly expect explainable risk decisions, not black-box scores — this report includes model performance and feature-importance views for exactly that reason.

🤖 AI Model Explanation (Plain Business Language)

Isolation Forest (the core scoring model) builds many random decision trees and checks how few splits it takes to isolate a transaction from the rest of the data. Fraudulent transactions tend to look different from the crowd, so they get isolated in fewer steps — fewer steps means a higher anomaly score, which means higher risk. Think of it like a bouncer sorting a crowd by how unusual someone looks, without needing to have seen that exact person cause trouble before.

Random Forest (used only for feature importance) is trained separately, with the fraud labels, purely to answer: which of the 30 input features mattered most to telling fraud apart from legitimate transactions? This turns the model into a business-readable ranking instead of a black box.

💡 Business Insights (10, generated from the data)

1. Approval rate is dominant — 99.78% of 19,355 transactions are approved; only 0.196% are blocked. The model is conservative, protecting checkout conversion.
2. Manual review queue is tiny — only 4 of 19,355 transactions (0.021%) need human review; capacity is not a bottleneck.
3. Blocked transactions carry higher amounts — avg scaled amount for blocked is 0.184 vs -0.0004 for approved — value-tiered rules could help.
4. Risk concentrates in specific hours — hour 2:00 has the highest average Risk_Score (2.13/100).
5. Peak blocked-transaction hour identified — hour 11:00 has the most blocks (8).
6. Off-hours risk is elevated — night block rate is 0.49% vs 0.196% overall.
7. Model precision is strong — 0.927 precision means most blocked transactions really are fraud.
8. Recall has room to improve — 0.792 recall means 10 real fraud cases are still scored as approved (see confusion matrix).
9. Risk score distribution is right-skewed — most transactions sit near zero risk; a small tail drives nearly all exposure.
10. No merchant/payment-channel granularity yet — adding these fields is the single highest-value next step for segmentation.

📋 Executive Summary

This project turns a pre-scored, anonymized transaction dataset into a working risk-operations tool. It automates the Approve / Review / Block decision using an Isolation Forest model, reports that model's performance transparently (precision 0.927, recall 0.792, AUC 0.986), and adds an operational layer — alerts, a searchable high-risk table, and a live scoring tool — that a human risk analyst could plausibly use day to day. Every number in this report is computed directly from the provided CSV; dataset limitations (no merchant/payment-channel data) are stated explicitly rather than papered over.

🔭 Future Scope

  • Add Merchant ID and Payment Method fields for true merchant- and channel-level risk views.
  • Move from a static, pre-scored CSV to a live-retraining pipeline on rolling transaction windows.
  • Add per-transaction SHAP explanations, not just global feature importance.
  • Connect the live risk checker to a real transaction stream instead of manual inputs.
  • Add case management — assign, track, and resolve manual-review items.
  • A/B test decision thresholds against business outcomes (approval rate vs. realized fraud loss).

🏁 Buildathon Submission Description (250 words)

Payment platforms process millions of transactions daily, each carrying fraud risk that must be assessed in milliseconds. This project builds a risk-operations dashboard around an Isolation Forest anomaly-detection model, scoring 19,355 anonymized transactions and routing each into Approve, Manual Review, or Block.

Beyond classification, the dashboard adds what a real risk team needs to act: eight live KPI cards, seven interactive visualizations, and a searchable, sortable high-risk transaction table. An AI Risk Operations panel surfaces live fraud alerts, a velocity-fraud warning derived from transaction time-gaps (9 flagged pairs), and off-hours monitoring — all computed directly from the data.

Model performance is reported transparently: a confusion matrix and ROC curve (AUC 0.986) benchmark predictions against ground truth, alongside precision (0.927), recall (0.792), and F1 (0.854). A Random Forest trained on the transaction's anonymized features produces a feature-importance ranking. A live "what-if" checker lets a reviewer test a hypothetical transaction instantly.

The project is intentionally honest about its data's limits — it does not fabricate merchant IDs or payment methods absent from the source CSV, instead using hour-of-day as an explicit proxy, with richer segmentation flagged as future work.
